## Resolved contracts

- Use two FastAPI/Uvicorn workers, synchronous SQLAlchemy, and PostgreSQL with its database-owned named volume. Pin compatible Python/base-image and uv versions during scaffolding and commit `uv.lock`; dependency resolution/build must prove compatibility before the phase exits.
- Proposed layout: `backend/pyproject.toml`, `backend/uv.lock`, `backend/src/autoassist/`, and `backend/tests/`; root `compose.yaml`, `Dockerfile`, `.dockerignore`, and `.env.example`. Within the package use `api/` for HTTP schemas/routes, `inventory/` for application records/use cases and later import parsing, `db/` for ORM/session setup/repositories, and `config.py` for settings. Create modules as needed, without empty integration frameworks.
- Dealerships have a stable UUID, unique configured slug, display name, and default connection name. A server-side configuration file declares dealerships and a mapping of connection names to `provider`, `model`, and `api_key_env`. Initially support `xai`; support multiple differently named connections without a fixed count. Never store credential values in SQLite or expose configuration through inventory responses. No caller-supplied provider URL or credential is accepted.
- Validate duplicate names/slugs, empty values, supported provider, and all dealership-to-connection references before startup writes. Missing API key values do not block this inventory-only slice; actual credential resolution and model validation belong to step 2 before chat admission. Examples label model placeholders explicitly. The roadmap's initial xAI choice supersedes the baseline's older “provider unselected” wording for this plan.
- Bootstrap configured dealerships in one transaction: insert new slugs and update names/default references while retaining IDs. Reject the whole configuration if invalid; never delete absent dealerships or inventory. Fail startup if a persisted dealership's default connection no longer resolves. Only report readiness after commit and a successful local database check. A crash before commit preserves the previous configuration; restart reapplies the same desired configuration safely.
- Vehicles belong to a dealership by non-null foreign key. Store stable application UUID, a source identity unique within that dealership, make, model, year, nullable price in integer cents, and nullable body type. Preserve display values and normalized trimmed/casefolded text keys for exact matching. Null means unknown; never invent a price or body type. The source-field mapping and additional useful detail fields are recorded in `docs/context/inventory/README.md`.
- `GET /health` returns `200 {"status":"ok"}` when storage is usable, otherwise sanitized `503`. It makes no external calls. `GET /dealerships/{dealership_id}/vehicles` returns `{items, next_after}`. Optional filters: `make`, `model`, `body_type` (trimmed, nonempty, maximum 100 characters), `year_min`/`year_max` (1886–2100), and `price_min`/`price_max` (nonnegative decimal amounts, at most two decimal places). All filters combine with AND; ranges are inclusive. Exact year uses equal bounds. A supplied price/body filter excludes unknown corresponding values.
- Search takes `limit` default 20, maximum 100, and optional UUID `after`; order by vehicle UUID and use `id > after`, fetching at most `limit + 1`. Return the last returned ID as `next_after` only when another result exists. Keep filters unchanged when paging. This is live inventory pagination, not a snapshot. Return price as a nullable two-decimal string. No unbounded result list or total-count query.
- `GET /dealerships/{dealership_id}/vehicles/{vehicle_id}` returns the public detail record. A missing dealership or a vehicle outside that dealership returns `404`; a valid empty search returns `200` with empty items. Malformed IDs, invalid filters, and reversed ranges return FastAPI's documented `422` validation envelope. Expected unavailable/busy storage returns `503 {"error":{"code":"storage_unavailable","message":"Inventory storage is unavailable."}}`; unknown resources use the same error envelope with `not_found`. Document actual error schemas in OpenAPI. Do not recategorize programming defects as expected storage errors.
- Scope every repository query by dealership, including detail lookup and pagination. Local path selection is not production authentication. Services take a trusted application scope so step 2's tools can reuse them without allowing the model to choose a dealership.

## Phase A — Start the API and establish durable configuration

2. Add dealership/vehicle models, constraints, and schema creation for a fresh database. Enforce foreign keys on every connection. Configure explicit transaction behavior supported by the selected Python/sqlite3 runtime and a five-second lock timeout, with no automatic write retries. Add a dealership/source-identity uniqueness constraint, price/year checks, and an index on `(dealership_id, id)`; add further indexes only where query evidence supports them. Bootstrap dealerships using the atomic behavior above. Startup creates missing tables but never resets existing data; schema changes require explicit development database recreation.

Align a bounded server drain with Compose's longer stop grace period. Verification uses temporary storage, never the development volume.

## Phase C — Import the real attachment and prove preservation

Prerequisites: phases A/B and `docs/context/inventory/data.csv`, both now available. The importer must require an explicit configured dealership slug because the file has no dealership column.

1. Use the recorded CSV mapping in `docs/context/inventory/README.md`: `stock_number` is the stable `source_id`; `price` is whole US dollars converted exactly to integer cents; `year`, `make`, `model`, and `body_type` map directly; preserve `trim`, `condition`, `mileage`, `exterior_color`, `drivetrain`, `transmission`, and `fuel` as vehicle details. Require an explicit configured dealership slug because the file has no dealership column.
2. Implement an offline CLI that reuses configuration/session setup without starting the web lifespan. Require the server to be stopped before import. Bound initial input to 20 MiB and 50,000 records with actionable rejection; revise these limits if attachment inspection demonstrates a need. Parse and validate the whole bounded input before opening the write transaction. Report row/field errors without dumping raw data. Reject duplicate source IDs, malformed required values, unsupported precision/units, and empty files. Missing optional values stay null.
3. Upsert the validated batch in one transaction keyed by `(dealership_id, source_id)`: insert new rows, update existing values, retain application UUIDs, and leave vehicles absent from the file untouched. Identical repeat imports produce no duplicates. No snapshot deletion or replacement of the database. Print inserted/updated/unchanged counts and exit zero only after commit. Validation failure writes nothing; mid-write failure rolls back the whole batch and exits nonzero. After uncertain commit or process death, rerunning the same file converges to the same inventory; no blind automatic retry.
4. Test a real representative attachment sample plus clearly labeled corrupt fixtures. Assert real-file expected count and selected field values, repeated-import stable IDs, changed-row updates, retained absent rows, dealership isolation, and full rollback after injected mid-batch/write/commit failure. Hold a competing lock and verify bounded failure with prior data intact.
5. On isolated test storage, gate an importer subprocess after writes but before commit, terminate it, wait for exit, and reopen storage: prior committed inventory remains and partial changes are absent. Rerun successfully, then recreate the backend container with the same disposable named volume and retrieve the imported records through HTTP. Test repeated startup preserves committed data. Delete only the explicitly identified disposable test volume during cleanup.

Implementation detail: add nullable typed detail columns to `Vehicle` and return them from the
existing vehicle detail response; no new search filters or endpoint are introduced. The CLI command is
`autoassist-import-inventory --file PATH --dealership SLUG --server-stopped`. It validates the
configured slug and complete CSV before engine creation, then initializes/bootstrap storage and
performs one atomic upsert. Focused tests use real temporary SQLite files, repository/event fault
injection, a lock holder, and a subprocess gate installed by the test rather than production-only
recovery hooks.

Exit evidence is complete: the supplied attachment imports completely; API filters/details match it; application restart and container recreation preserve IDs and values; and failed or interrupted imports leave no partial writes. README contains verified mount/import/re-import/reset guidance, format rules, error recovery, and omissions.
