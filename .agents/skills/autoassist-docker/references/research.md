# Docker skill research

Reviewed 2026-09-10 (America/Chicago). Primary documentation informs the mechanics below; the shared project baseline supplies the stack and scope decisions. Recheck version-sensitive options against installed versions when implementing.

- [Docker volumes](https://docs.docker.com/engine/storage/volumes/): volumes outlive containers and mounts obscure image contents. Agent consequence: inspect the actual mount/database path, preserve the named volume, and prove durability through recreation. Never treat rebuilding an image as proof of persisted data. Named SQLite directory storage and single-worker exclusivity are project decisions.
- [Docker build practices](https://docs.docker.com/build/building/best-practices/): small build contexts, dependency caching, pinned image inputs, and non-root execution improve reproducibility. Agent consequence: inspect `.dockerignore` relative to the real context and test effective mounted-directory permissions instead of assuming Dockerfile ownership suffices.
- [uv Docker integration](https://docs.astral.sh/uv/guides/integration/docker/): supports locked synchronization, dependency-layer caching, and avoiding host virtual environments in development mounts. Agent consequence: enforce lock consistency, choose a container-owned environment path, and preserve check dependencies; do not blindly copy multi-stage examples into a small project.
- [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/): requires a lockfile, fails when manifest and lock disagree, removes existing installation, and does not update lockfiles. Agent consequence: use it for reproducible container checks and preserve dependency-shaping configuration used to generate the lock.
- [Compose networking](https://docs.docker.com/compose/how-tos/networking/): service discovery and container ports apply within the Compose network; published ports serve host access. Agent consequence: test browser connectivity separately from container-to-container success. Relative frontend proxy requests and localhost publishing are project choices.
- [Compose startup order](https://docs.docker.com/compose/how-tos/startup-order/): startup ordering alone does not establish readiness; health conditions can gate dependent startup. Agent consequence: use bounded readiness evidence and probes available in the image, not sleep-based assumptions.
- [Compose service reference](https://docs.docker.com/reference/compose-file/services/#stop_grace_period): the grace period limits how long shutdown waits before forced termination. Agent consequence: align it with the application's drain budget and verify recovery after forced stop separately. Interrupted-request behavior remains defined only by the shared lifecycle.

These sources do not prescribe AutoAssist's one-worker SQLite architecture, runtime provider, API endpoint names, or repository commands. The skill intentionally supplies no fictional executable project commands or container scaffolding.
