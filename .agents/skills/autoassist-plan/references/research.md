# Planning skill research

Reviewed 2026-09-10 (America/Chicago).

- [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills), current documentation: scoped descriptions determine selection; metadata precedes body loading; repository skills live in `.agents/skills`; invocation policy can disable implicit selection. Applied as one planning entry point, a small specialist index, selective body reads, and explicit invocation metadata. Test discovery separately from file validation.
- [OpenAI Cookbook: Using PLANS.md for multi-hour problem solving](https://developers.openai.com/cookbook/articles/codex_exec_plans), published 2025-10-07, currently marked archived: useful planning patterns are observable outcomes, concrete locations/checks, resolved ambiguities, feasibility experiments, and maintained decisions. Use these stable workflow ideas, not its model recommendations or mandatory long template. The project requires short proportional plans, permits breaking changes, and does not adopt that recipe's legacy-path or universal commit conventions.
- Local `skill-creator/SKILL.md` and `references/openai_yaml.md`: instruction-first design, precise triggers, progressive disclosure, proportional constraints, and structural validation. No script is needed for open-ended planning decisions.

Project decisions come from `AGENTS.md`, `docs/plans/project-skills.md`, and `docs/stack-baseline.md`, not upstream documentation: three implicit orchestrators, eleven explicitly selected specialists, no automatic agent fanout, agent-owned verification, planning-only scope, assignment-inventory constraints, and preserved explicit-only tech-stack workflow. The inventory later became available at `docs/context/inventory/data.csv`. The user approved extraction of the shared baseline into `docs/stack-baseline.md`; planning reads that reference without implicitly invoking tech-stack or duplicating its lifecycle table.

Failure modes targeted: vague steps that defer design to implementation; imaginary commands; unneeded human gates; broad specialist loading; plans that omit persisted failure state or async/query bounds; unverified browser handoffs; and planning requests accidentally becoming feature implementation. Evidence is a finishable plan with concrete affected boundaries, expected outcomes and checks, narrowly scoped unresolved external inputs, and no application edits on planning-only work.
